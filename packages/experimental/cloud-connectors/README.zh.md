# @deepseek-ai/dsh-experimental-cloud-connectors

[English](README.md) | 中文

## 概述

在插件页面提供两个独立的连接：**AWS** 和 **Supabase**。安装或启用此包后**不会**自动登录任何服务。每个连接初始均为**未连接**，用户必须在当前设备点击**连接**，完成浏览器登录并确认允许代理使用的 MCP 工具。

## 使用本包

Desktop 首次创建的配置包含[云服务连接组合包](../cloud-connectors-bundle/README.zh.md)。进入**插件 → AWS** 或**插件 → Supabase**，点击**连接**并在浏览器中完成提供方登录。登录后将列出可用 MCP 工具；**默认勾选全部**。用户可取消不需要的工具，然后点击**启用选中的工具**。只有显式确认后，工具才会出现在代理的工具列表中。

凭据、授权码、刷新令牌及客户端注册信息只保存在本地 Host 的 Harness 凭据服务中，不进入组合包、源代码、界面响应或 Git 仓库。每台设备与每个配置需要分别连接。**断开此设备连接**会移除本地授权和工具，但不会撤销提供方的远程令牌；必要时须到提供方另行撤销。

提供方地址为固定值：AWS 托管 MCP 服务 `https://aws-mcp.<region>.api.aws/mcp`（选择受支持的区域），或官方 Supabase 服务 `https://mcp.supabase.com/mcp`。Host 将验证地址。连接使用 MCP OAuth 2.1 浏览器流程，并验证一次性本地回调的 state。

## 安全边界

- 勾选全部工具**不会**授予 AWS IAM 权限，也不会绕过 Supabase 项目权限或 RLS。身份认证和服务端授权由服务提供方控制。
- 启用工具意味着代理可以使用它；对于可写操作，Harness 的工具审批策略仍可能要求进一步确认。请检查每项工具的描述。
- 认证失败或客户端注册未获批准时必须拒绝连接。禁止将密钥或凭据提交到 Git。
- AWS 托管 MCP 服务可能只允许 AWS 已批准的客户端动态注册；Harness 分支不会自动获批。如果登录失败，需要联系 AWS 申请客户端注册。
- OAuth 回调绑定 `127.0.0.1` 的随机本地端口。若浏览器与 Host 不在同一台机器上，初版尚不支持重定向桥接；目前面向本地 Desktop。

## 模型体验

确认前 AWS/Supabase 工具对模型**完全不可见**。确认后，选中的工具通过现有 `mcp__<provider>__<tool>` 命名空间提供；不额外注入提示词或模型上下文。

## 已知限制

- 浏览器认证取决于服务提供方是否支持公共 OAuth 客户端或已批准客户端。单元测试没有使用真实 AWS/Supabase 账户登录。
- 目前通过 Desktop 使用的 Web 插件页面操作；没有独立的 macOS、Windows、Linux 原生登录二进制文件。TypeScript 与 HTTP 回调实现与平台无关。
- 连接时读取工具列表；如服务端新增工具，需要重新连接并审核新的权限列表。
